# 적정 재고일수 자동 산출

요청자 엑셀(재고등급·안전재고 점검)을 읽어 SKU별 적정 재고일수를 세 기준(가중평균·실적기준·FCST기준)으로 계산하고,
엑셀 Summary 값과 대조한 뒤, 이후 실제 출고로 사후 검증하는 프로그램이다.

## 설치

Python 3.12 이상과 [uv](https://docs.astral.sh/uv/)가 필요하다.

```
uv sync
```

## 실행

```
uv run python -m safety_stock BASE.xlsx --actual ACTUAL.xlsx -o out/결과.xlsx
```

| 옵션 | 설명 | 기본값 |
| --- | --- | --- |
| `BASE.xlsx` | 요청자 기준 엑셀(구매마스터·출고·SCM FCST·현재고·Summary 시트 포함) | 필수 |
| `--actual` | 실제 출고 엑셀(사후 검증용, `출고실적` 시트) | 필수 |
| `-o`, `--out` | 결과 xlsx 경로 | 필수 |
| `--actual-last-week` | 실적 마지막 주차(WK01부터) | 31 |
| `--fcst-weeks` | 사용할 FCST 앞 주 수 | 13 |
| `--validation-weeks` | 검증 주차 범위 | 35-43 |

입력 오류(시트·열 누락 등)는 메시지만 출력하고 종료 코드 2로 끝난다.
명령줄 값도 실행 전에 검사한다: `--fcst-weeks`는 1 이상, `--actual-last-week`는 검증 시작 주차보다 작아야 하고
(검증용 실제 출고가 계산에 섞이지 않도록), `--validation-weeks`는 `A-B` 형식이며 A ≤ B여야 한다. 어기면 종료 코드 2.
끝나면 처리 SKU 수, 가중평균 엑셀 일치 SKU 수, 재고등급 엑셀 일치 SKU 수(`재고등급 엑셀 일치 SKU 수: x/y`), 결과 경로를 출력한다.

구매마스터 시트의 필수 열은 SKU, 재고등급, 실적 가중치, FCST 가중치, 리드타임(일), 안전재고 값, 구매단가, 기초재고, 기말재고, FCST, 리드타임, 품질이슈다.
단가·회전율·리드타임·품질이슈는 등급 열과 점수 열로 각각 나와야 하며(회전율은 값·등급·점수로 3번), 첫 번째가 등급(회전율은 값), 다음이 점수다. 모자라면 입력 오류로 끝난다.

## 테스트

```
uv run pytest
```

`tests/test_real_data.py`는 `data/` 폴더의 실제 파일로 엑셀 값을 재현하는 수용 테스트이며, 파일이 없으면 건너뛴다.

## 결과 시트

- `산출결과`: SKU당 1행. 공통 입력, 기준별(`가중평균_`·`실적기준_`·`FCST기준_`) 수요·σ·LT평균수요·LT수요편차·Z·안전재고·ROP·적정재고일수·안전재고일수·현재고일수·발주, 기존안전재고일수, 기존수기_적정재고일수(리드타임 + 기존안전재고일수, 표시용), 점검메모.
- `재고등급`: 구매마스터 SKU별 재고등급 계산 과정(회전율, 단가·회전율 백분위와 등급, 점수, 종합, 재고등급)과 엑셀 값(회전율·단가등급·회전율등급·종합·재고등급)을 함께 보여 준다. 판정(일치/불일치/비교불가)은 단가등급·회전율등급·종합·재고등급 4개를 대상으로 하며 회전율 값은 판정에 쓰지 않는다. 계산 불가인데 엑셀에 값이 있으면 불일치다. 계산 등급이 `산출결과`의 Z값에 쓰인다.
- `엑셀대조`: 계산값과 엑셀 Summary 값을 기준·필드별로 비교한 행과 상태, 그 SKU의 판정(일치/불일치/비교불가). 필드는 수요·σ·LT평균수요·LT수요편차·안전재고·ROP·적정재고일수·안전재고일수·현재고다. 현재고는 기준과 무관한 입력값이지만 세 기준 행 모두에 같은 비교가 들어간다. 허용오차는 엑셀 표시 자릿수 반올림 ±0.5단위 + 엑셀값의 0.5%.
- `검증_SKU`: 이후 실제 출고와 비교한 SKU별 결과. 기준별 목표재고량, 예측 오차, 오차기여율(|수요오차| ÷ 그 기준 전체 Σ|수요오차|), LT 수요 방어 여부, 실제 기준 재고일수, 입력 누락으로 채점에서 제외된 사유. 기준 파일에만 있는 SKU는 메모 `실적파일없음`, 실제 출고 파일에만 있는 SKU는 메모 `계산대상없음`으로 끝에 붙는다(채점하지 않음).
- `검증요약`: 범위와 기준별 WAPE, 편향, 결품방어율, 실제 기준 재고일수 중앙값. 기준은 `기존수기`(구매마스터의 기존 안전재고 값은 MP UI에 등록한 제품별 일별 안전재고(일)이므로 목표재고량 = 가중평균 LT수요 + 기존 안전재고일수 × 가중평균 일평균수요), `가중평균`, `실적기준`, `FCST기준`이며, 보정계수가 0이거나 3보다 큰 SKU는 실적기준·FCST기준을 채점에서 빼고(제외사유 `보정계수이상`, 가중평균·기존수기는 그대로 채점) 그래서 `공통`·품목그룹 범위에서도 빠진다. 입력이 없어 채점에서 빠진 SKU는 `검증_SKU`의 제외사유에 나온다. 범위 정의:
  - `전체`: 기준별로 채점 가능한 SKU를 모두 쓴다. 기준마다 SKU 수가 다를 수 있다.
  - `공통`: 기준 간 공정 비교용. 수요 지표는 세 산식 기준 모두 수요오차가 있는 SKU, LT 지표는 네 기준 모두 방어 여부가 있는 SKU만 쓴다.
  - 품목그룹(그룹명 그대로): `공통`의 SKU를 그 그룹으로 거른 것. 그룹 안에서도 기준마다 SKU 수가 같다.
- `적용기준`: 이번 실행 시각, 입력 파일, 주차(FCST 첫·마지막 주차 라벨 포함)·산식·Z값, 대조 허용오차, 범위 정의, 검증 규칙 등.

## 점검메모

`산출결과`의 점검메모에 붙는 문구(여러 개면 쉼표로 함께):

| 메모 | 뜻 |
| --- | --- |
| `구매마스터없음` | 출고·FCST에만 있고 구매마스터에 없는 SKU |
| `등급없음` | 계산 재고등급이 없음(`재고등급` 시트 메모에 사유, Z 관련 값 비움) |
| `수요없음` | 가중평균 주수요가 0(일수 비움) |
| `실적없음` | 출고 시트에 SKU가 없거나, 행은 있어도 실적 주차 값이 모두 빈 칸 |
| `FCST없음` | SCM FCST 시트에 SKU가 없음 |
| `가중치없음` | 실적 가중치나 FCST 가중치가 비어 있음 |
| `가중치합오류` | 두 가중치의 합이 1이 아님(값은 그대로 사용) |
| `리드타임없음` | 리드타임이 없거나 0 이하 |
| `보정계수없음` | 과소예측 보정계수가 없음(실적·FCST기준 비움) |
| `보정계수이상` | 보정계수가 0이거나 3보다 큼(산출결과 계산은 그대로, 사후 검증에서는 실적·FCST기준 채점 제외) |

## 가상 보완본

산식과 어긋난 칸만 산식 결과로 채워 새 통합문서(`..._가상보완.xlsx`)를 만든다. 원본은 건드리지 않는다.

> 경고: 결과는 발표용 가상 데이터다. 실제 재고·판매 값이 아니므로 업무 판단에 쓰지 않는다.

```
uv run python -m safety_stock.virtual_data 보완본.xlsx -o 보완본_가상보완.xlsx
```

값만 있는 통합문서(구매마스터·Summary·출고·FCST·현재고 시트에 수식 없음)만 받는다. 바꾸는 칸은 3종류다.

1. 구매마스터 기초·기말재고: 회전율 분모가 0인 행을 `FCST ÷ 중앙회전율`(최소 1)로 채운다.
2. 구매마스터 등급 계산 칸(회전율, 단가·회전율 등급, 점수, 종합, 재고등급): 산식 결과와 다른 칸만 다시 쓴다.
3. Summary 시트: 계산값과 불일치하거나 비어 있는 칸을 계산값으로 바꾸고, 재고등급·Z값계수를 계산 등급에 맞춘다.

바꾼 칸은 모두 `가상보완_내역` 시트(시트, 셀, 구분, 원래 값, 새 값, 사유)에 남는다. `구분`은 `변경`(칸 값을 바꿈)과 `기록만`이다. 산식으로 채울 수 없는 칸은 바꾸지 않고 새 값을 비운 채 `기록만`으로 사유를 남긴다.
명령줄은 `바꾼 칸 수: N`(`변경`만)과 `채우지 못하고 기록만 한 칸: M`을 따로 출력한다. 손상됐거나 xlsx가 아닌 파일은 종료 코드 2로 끝난다.

주의: 채운 16행 같은 가상 재고가 회전율 순위(백분위) 배열에 들어가므로 채우지 않은 다른 SKU의 회전율 등급·재고등급·Z값이 바뀔 수 있다. 내역 사유로 구분한다: 채운 행 자신의 칸은 `재고등급 산식 재계산`, 채우지 않은 행에서 순위 변화로 달라진 구매마스터 칸은 `가상 재고로 회전율 순위 모집단 변경`이다(그 여파로 바뀐 Summary 칸은 기존 사유를 쓴다).

## 가중치 탐색

품목그룹별 실적가중치(FCST가중치 = 1 - 실적가중치)를 데이터로 다시 고르고, 현재 가중치와 비교한다.

```
uv run python -m safety_stock.weight_search BASE.xlsx --actual ACTUAL.xlsx -o out/가중치탐색.xlsx [--select-weeks 35-38] [--holdout-weeks 39-43]
```

- 구간: 선택 구간(기본 W35~W38) 실제 출고로 고르고, 검증 구간(기본 W39~W43)에서 현재와 비교한다. 참고용 전체 구간은 선택 시작~검증 끝이다. 선택에는 검증 구간 실제 출고를 쓰지 않는다.
- 후보: 실적가중치 0.0~1.0(0.1 간격).
- 규칙: 선택 구간 가중평균 수요 WAPE가 가장 낮은 w를 고른다. 동점이면 현재 w에 가까운 쪽, 그래도 같으면 작은 쪽이다. 수요오차가 있는 SKU가 5개 미만인 그룹은 모든 SKU를 합친 WAPE 최소 w(공통최적)를 쓴다. 그룹 자신의 WAPE를 구할 수 없으면(실제 합 0 등, SKU 수와 무관하게 작은 그룹 포함) 공통값 대신 현재 w를 유지한다.
- 선택 구간 시작은 실적 마지막 주차(기본 31) 뒤여야 한다(어기면 종료 코드 2). 원래 가중치가 비어 있는 SKU와 `현재유지` 그룹은 탐색 가중치를 적용하지 않아 현재와 탐색이 같은 SKU 집합으로 비교된다.
- 결과 시트: `후보성능`(범위 x w별 WAPE), `선택가중치`(현재·선택 w와 방식), `검증비교`(검증·전체 구간의 현재 vs 탐색 지표, SKU가 0개인 행 제외. 그룹 범위는 '공통' 집합을 그룹으로 거른 것이라 `선택가중치`의 SKU 수와 다를 수 있다), `적용기준`.
- 한계: 선택 구간이 4주뿐이고 통계적 유의성 검정이 없다. 개선 주장은 검증 구간 수치로만 한다.

## 구조

- `purchase_master`: 구매마스터 읽기, 재고등급 계산
- `mp_simulation`: SCM FCST 등 MP 시뮬레이션 결과 읽기
- `inventory_days`: 출고·현재고·Summary 읽기, 계산, 대조, 검증, 결과 작성
- `virtual_data`: 가상 보완본 생성
- `weight_search`: 품목그룹별 가중치 탐색과 결과 작성
- `common`: 공통 엑셀 유틸

## 발표자료

결과 xlsx에서 발표 숫자를 읽어 PPT를 만든다. 숫자는 손으로 적지 않는다. 처음 한 번 `presentation` 폴더에서 `npm install`을 실행한다.

```
uv run python presentation/extract.py
node presentation/build.js
powershell -File presentation/render.ps1
```

- 결과: `out/발표_적정재고일수.pptx`(장별 그림은 `out/render/slide-NN.png`)
- `presentation/data.json`은 업무 수치라 저장소에서 제외한다(`extract.py`가 다시 만든다).
