# 발표자료 공개본 설계 (대학원 배포용, 15장)

- 작성일: 2026-11-20
- 상태: 사용자 승인(구성안 15장 + "문서에 서론·본론·결론이라는 말은 쓰지 않는다")
- 사내본: `out/발표_적정재고일수_AI.pptx`(36장, `presentation/build.js`)는 그대로 둔다.

## 1. 목적과 청중

- 청중: 전 대학원생. 발표 후 파일이 배포된다.
- 목적: 기업 보안 정보를 드러내지 않고, "테스트용 데이터로 개발·검증한 AI 기반 적정 재고일수 산출 시스템"으로 보이게 한다.
- 사용자 지시
  - 상세 제품명과 전체 수식은 넣지 않는다. 일부만 보여 준다.
  - 15장 안으로 줄인다. 핵심은 깊게 다루고 나머지는 발표용으로 간단히 다룬다.
  - 숫자는 필요하다. 데이터는 "테스트 데이터"라고 명시하면 대부분 쓸 수 있다.
  - 도입 → 전개 → 마무리 흐름이 명확해야 한다. 단, 문서에 "서론·본론·결론"이라는 말은 쓰지 않는다.
  - 가장 관심 있는 부분은 AI 기술이다. 처음부터 프로젝트를 "어떤 AI 기술을 활용한 무엇"으로 명시한다.
    - 표지: 머신러닝 그리드 탐색과 시계열 검증을 활용한 적정 안전재고일수 산출 시스템
    - 요약과 목표 장도 AI 기술을 앞에 둔다.
    - 정직성: 학습된 예측 모델이 아니다. 머신러닝의 모델 선택(하이퍼파라미터 탐색) 방식을 가중치에 적용했다고 쓴다.
  - 최종 목표는 MLOps이고, "현재 단계는 여기"로 표현한다(사용자 지시).
    - 표지: "MLOps 기반 적정 안전재고일수 산출 시스템", 부제는 1단계 AutoML(그리드 탐색 · 시계열 검증)
    - 5장: MLOps 파이프라인 전체. 구현 단계는 청록, 계획 단계는 회색으로 칠하고 "현재 여기" 표시
    - 14장: Google MLOps 성숙도 Level 0/1/2와 현재 위치(Level 0→1 진입), 목표 대시보드 목업
    - 목업 표시(내 판단): "목표 화면(구상) · 예시 값". 운영 중인 것처럼 보이게 하지 않는다. 청중이 물었을 때 사실과 어긋나지 않게 하기 위해서다.

## 2. 가리는 것과 남기는 것 (사용자 선택: A안)

| 항목 | 처리 |
|---|---|
| 품목그룹 코드 | 그룹 A~G로 바꾼다. 가중평균 수요 채점 SKU 수가 많은 순서이고, 같으면 코드 순이다. 대응표는 코드에 적지 않고 실행할 때 data.json에서 만든다. |
| SKU 코드·제품명 | 쓰지 않는다. 사례는 "품목 X"로 쓴다. |
| 수량 | 출고량, 발주점, 현재고, 주수요 합계 같은 절대 수량은 쓰지 않는다. 비율(%), 일수, 배수, SKU 수만 쓴다. |
| 산식 | 일반식 두 개만 쓴다. 가중평균 수요 = w·실적 + (1−w)·예측, 안전재고 = Z·σ·√(LT). 산식 체인 전체, 등급별 Z값, 재고등급 점수·백분위 규칙, 보정계수는 쓰지 않는다. "등급별 서비스 수준(Z) 적용"까지만 쓴다. |
| 사내 이름 | MP, ITSM, SCM, WMS, 구매마스터 같은 시스템·시트 이름은 쓰지 않는다. 일반 용어로 바꾼다: 수요 예측, 출고 실적, 재고 시스템. |
| 날짜 | 8/24, 8/28 같은 실제 날짜는 쓰지 않는다. 주차 번호(W01~43)는 상대 기간으로 남긴다. |
| 근거 줄 | 파일·시트 경로를 지운다. 꼬리말 왼쪽은 "AI 기반 적정 재고일수 산출 · 테스트 데이터 기반"으로 하고, 오른쪽에 쪽 번호를 둔다. 작성자는 비워 둔다. |
| 데이터 표기 | "테스트 데이터셋(비식별 처리)"으로 쓴다. 표지, 데이터 장, 한계 장, 꼬리말에 표시한다. |

## 3. 구성 (15장, ◆ 깊게 · ○ 간단히)

장 이름에 "서론·본론·결론"을 쓰지 않는다. 대신 태그와 흐름으로 구분한다. 문제 → 목표 → 방법 → 결과 → 의미 순서다.

1. 표지
2. 한 장 요약: 문제 / 방법 / 결과 KPI(검증 오차율, 탐색 조합 수, 등급 일치)
3. ○ 문제: 고정 안전재고일수 4종과 정해 둔 가중치로는 수요 변화를 반영하지 못한다.
4. ○ 목표·연구 질문과 테스트 데이터 개요: 품목 수, 그룹 수, 기간 구분(학습 W01~31 / 선택 / 검증)
5. ○ 시스템 구성: 데이터 검사 → 산출 → 등급 → AI 탐색 → 검증 → 리포트
6. ○ 산출 방법: 일반식 두 개, 등급별 서비스 수준
7. ◆ AI 기법: 그리드 탐색, 시계열 분할 검증, 과적합 방지(작은 그룹 합산), (+ 통계 모형·MLOps·생성형 AI 에이전트는 짧게)
8. ◆ 탐색 설계: 주차 타임라인(선택 W35~38 / 검증 W39~43), 규칙 4가지, 77번 계산 = 1,949만 조합 최적인 이유
9. ◆ 후보 전체 채점 히트맵: 그룹 A~G × w, ★ 선택, ○ 현재
10. ◆ 결과 1: 검증 구간 오차율 33.1% → 28.3%. 결품 방어율 하락도 함께 표시한다.
11. ◆ 결과 2: 그룹별 전후 비교와 개선 기여 몫(쏠림)
12. 사례: 품목 X의 안전재고가 고정 45일에서 산식 6.0일로 바뀐다. 실제 출고로 방어를 확인한다. 수량 없이 일수와 % 차이로 보여 준다.
13. 해석과 한계: 테스트 데이터, 선택 4주, 유의성 검정 없음, 결품 방어는 대리 지표
14. ○ 향후 과제와 MLOps 운영안
15. 정리 3가지 + 질의응답

## 4. 접근 방식

- 검토한 방식
  - **(선택) 별도 원본 `presentation/build_public.js`**: 사내본 원본을 건드리지 않아 사내본이 깨질 위험이 없다. 양식 도우미 함수는 복사해 쓴다. 프로젝트가 일회성이라 중복은 감수한다.
  - **기존 `build.js`에 `--public` 옵션 추가**: 장마다 분기가 생겨 사내본과 공개본이 서로를 깨뜨리기 쉽다.
  - **사내본 pptx를 손으로 고치기**: 숫자 자동 갱신과 금지어 검사를 할 수 없다.
- 숫자는 지금처럼 `presentation/data.json`(extract.py 결과)에서 읽는다. 손으로 적은 숫자는 없다.
- **금지어 검사 `presentation/leak_check.py`**
  - 결과 pptx의 모든 글자(슬라이드 XML과 문서 속성)를 훑는다.
  - 금지어 목록을 만든다.
    - data.json에서 가져오는 것: 그룹 코드, SKU 코드, 제품명
    - 고정 목록: 사내 시스템명, 날짜 표기, Z값, 파일 확장자 등
  - 하나라도 나오면 실패로 끝난다.
  - 그룹 코드처럼 짧은 영문 토큰은 영문자 경계로 찾는다.
- 출력: `out/발표_적정재고일수_공개본.pptx`, 렌더링 `out/render_public/slide-NN.png`

## 5. 하지 않는 것

- 숫자를 바꾸거나 지어내지 않는다. 실제 결과 그대로이며, 표기만 비식별 처리한다.
- 사내본(36장)은 수정하지 않는다.
- 부록 장은 넣지 않는다(15장 제한).
