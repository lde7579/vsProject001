# 발표자료 공개본 개정 설계: 목표(일별 안전재고 자동 산출)를 중심에 두기

- 작성일: 2026-11-20
- 상태: 사용자 승인(15장 구성안 + 표지·요약에서 "1단계"·MLOps 현재 위치를 부각하지 않음)
- 대상: 공개본만 고친다(`presentation/build_public.js` → `out/발표_적정재고일수_공개본.pptx`). 사내본(36장)은 그대로 둔다.
- 앞선 설계: `2026-11-20-발표자료-공개본-design.md`. 비식별 규칙(§2)과 완료 확인(§6)은 그대로 따른다.

## 1. 왜 고치나 (사용자 지시)

기존 공개본에는 가장 중요한 **목표**가 빠져 있었다.

- 현업은 일별 안전재고(일)를 직접 산정해 넣는다. 그런데 품목마다 계산할 수 없어서 대부분 비슷한 값을 넣을 수밖에 없다. 테스트 데이터에서는 80 SKU가 21·30·42·45일 4가지 값에 몰려 있다.
- 목표는 **품목별로 자동 산출되는 일별 안전재고값**을 만드는 것이다.
- 대표 대상은 **가중평균 기준 안전재고**다. 비교군은 두 가지다.
  - **실적기준 안전재고**: 실제 출고 실적만으로 수요를 잡는다.
  - **FCST기준 안전재고**: 기존 수요예측 엔진이 내는 예측값만으로 수요를 잡는다.
- 이 목표는 가장 핵심이므로 빠지면 안 된다.
- 실적 가중치와 FCST 가중치는 현업이 자체 공식으로 계산해 넣은 값이다. 터무니없는 수치가 아니다.
  - 따라서 "근거 없는 가중치"라는 표현은 모두 지운다.
  - AI 탐색은 현업 가중치를 출발점으로 삼아 데이터로 **확인하고 보정하는** 단계로 쓴다.
- 표지에 "1단계", "MLOps 현재 위치" 같은 말을 쓰지 않는다. 단점이므로 부각할 필요가 없다.
  - 같은 이유로 요약 장의 "Level 0→1 진입"과 구성 장의 "현재 여기" 표시도 지운다. **(내 판단)**
  - 구현한 단계와 계획한 단계는 색으로만 조용히 구분한다. 청중이 물었을 때 사실과 어긋나지 않게 하기 위해서다.

## 2. 이야기 흐름

목표 → 세 기준 비교 → AI 보정 → 정리 순서로 간다. 세 기준 비교가 앞에 오고, AI 탐색은 그 뒤에 나오는 보정 단계다.

| # | 장 | 핵심 내용 · 근거 데이터 |
|---|---|---|
| 1 | 표지 | 제목 "AI 기반 품목별 일별 안전재고 자동 산출 시스템". 부제는 가중평균 기준 산출, 실적·FCST기준 비교, 그리드 탐색·시계열 검증 보정이다. 1단계·현재 위치는 쓰지 않는다. |
| 2 | 한 장 요약 | 목표 / 비교 / AI 보정 / 핵심 KPI(4종 → 품목별 값, 가중평균 오차율 29.0%, 보정 후 28.3%). 주의 1개(결품 방어율). |
| 3 | 문제 | 현업 산정 값이 4종에 몰림(`days.old_safety_levels`). 카드 3개: 비슷한 값 일괄 입력 / 수요·리드타임 변화 미반영 / 사후 채점 없음. "현업 산정 방식이 틀렸다"가 아니라 "품목마다 계산할 수단이 없다"로 쓴다. |
| 4 | 목표와 비교 설계 | 목표 한 줄. 세 기준 카드: 가중평균(대표), 실적기준(실적 기반), FCST기준(기존 수요예측 엔진 출력 기반). 현업 가중치 설명: 그룹별 자체 공식, 0.1~0.9. 연구 질문 3개(세 기준 중 실제에 가장 가까운 것 / 품목별 값이 나오는가 / AI 보정으로 더 나아지는가). 테스트 데이터셋 표. |
| 5 | 시스템 구성 | 파이프라인: 검사 → 세 기준 산출 → 등급 → AI 보정 → 시계열 검증 → 리포트, 그 뒤에 승인·모니터링·재탐색. 구현은 청록, 계획은 회색이다. "현재 여기"와 Level은 쓰지 않는다. 기존 14장(MLOps 로드맵·목표 화면 구상)은 뺀다. |
| 6 | 산출 방법 | 세 기준이 수요를 잡는 방식을 말로 쓴다. 일반식은 두 개다: 가중평균 수요 = w·실적 + (1−w)·예측, 안전재고 = Z·σ·√LT. 안전재고일수 = 안전재고 ÷ 일평균 수요. 보정계수는 쓰지 않는다. 등급 116/116은 짧게 다룬다. |
| 7 | 결과 1 | 자동 산출하면 4종이던 값이 품목마다 달라진다. 같은 74 SKU에서 기존·가중평균·실적기준·FCST기준의 중앙값, 고유값 수, P10~P90을 보여 준다. 가중평균은 범위가 안정적이고, 실적·FCST기준은 극단값이 나온다. |
| 8 | 사례 | 품목 X: 기존 45일 → 가중평균 6.0일 · 실적기준 · FCST기준 값. 실제 출고 방어 여부는 네 기준 모두 보여 준다. 수량은 쓰지 않는다. 반대 사례 한 줄도 넣는다. |
| 9 | 결과 2 | 실제 출고 채점(공통 74 SKU, W35~43). 오차율은 가중평균 29.0%, FCST 35.1%, 실적 44.9%다. 방어율과 재고일수도 보여 준다. 기존 수기는 방어율 69.0%가 가장 높지만 재고일수 44.1일로 재고를 가장 많이 든다. 이 맞바꿈을 적는다. |
| 10 | 결과 3 | 그룹 A~G × 세 기준 오차율 히트맵(`metrics[그룹]`). 그룹마다 가장 맞는 기준이 다르다 → 그룹별로 가중치를 보정할 여지가 있다. |
| 11 | AI 기법과 탐색 설계 | 그리드 탐색, 시계열 분할 검증, 과적합 방지(작은 그룹 합산). 주차 타임라인과 77번 계산 = 1,949만 조합. 기존 7·8장을 합친다. |
| 12 | 탐색 히트맵 | ○ 현업 w, ★ 선택. 해석: 대형 그룹 A·B는 현업 w가 최적과 가깝다(0.4·0.9%p 차이). 그룹 C에서 보정 여지가 컸다. |
| 13 | AI 보정 결과 | 검증 구간 W39~43에서 33.1% → 28.3%. 그룹별 감소 몫, 결품 방어율 하락을 함께 보여 준다. 기존 10·11장을 합친다. |
| 14 | 해석과 한계 | 기존 13장에 세 기준 비교의 한계(같은 기간 채점, 유의성 검정 없음)를 더한다. |
| 15 | 정리 | 3가지(목표 / 비교 결과 / AI 보정)와 다음 과제(서비스 수준 조정, 주간 재탐색, 운영 적용). 질의응답. |

## 3. 표현 원칙

- 사내 시스템명 대신 쓰는 말: "MP 엔진" → "기존 수요예측 엔진". 금지어 검사기가 `MP`를 막는다.
- 기준 이름: 가중평균 기준 / 실적기준 / FCST기준. FCST는 금지어가 아니다. 처음 나올 때 "FCST(예측)"로 풀어 쓴다.
- 현업 가중치: "현업 산정 가중치" 또는 "현업 w"로 쓴다. 기존의 "현재 w"는 "현업 w"로 바꾼다.
- 나빠진 지표는 숨기지 않는다.
  - 가중평균의 결품 방어율은 기존 수기와 실적기준보다 낮다.
  - AI 보정 후 결품 방어율은 62.3% → 60.9%로 낮아졌다.
- 기간이 다른 두 숫자를 섞지 않는다. 장마다 범위를 적는다.
  - 세 기준 비교(29.0%): W35~43, 공통 74 SKU
  - AI 보정(33.1% → 28.3%): 검증 구간 W39~43, 77 SKU

## 4. 데이터 추가 (`presentation/extract.py`)

- `safety_distribution`에 `bases`를 추가한다.
  - 대상은 기존·가중평균·실적기준·FCST기준 네 값이 모두 있는 SKU다.
  - 기준별로 중앙값, 최솟값, 최댓값, P10, P90, 고유값 수(소수 1자리 기준), 기존보다 짧아진 SKU 수를 넣는다.
- `case_dict`에 실적기준·FCST기준 값을 추가한다.
  - 안전재고일수, 적정재고일수, LT 수요 방어 여부, 실제 기준 재고일수
- 추가하는 함수는 단위 테스트로 확인한다(`tests/presentation/test_extract.py`, 작은 가짜 행으로).

## 5. 하지 않는 것

- 사내본은 수정하지 않는다.
- 숫자는 손으로 적지 않는다. 모두 data.json에서 가져온다.
- 부록은 넣지 않는다.
- 목표 화면(구상) 목업은 넣지 않는다.
