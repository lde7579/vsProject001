# 가중치 탐색 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 품목그룹별 실적가중치를 선택 구간(W35~38)으로 고르고, 검증 구간(W39~43)에서 현재 가중치와 비교하는 결과 xlsx를 만든다.

**Architecture:**
- 기존 파이프라인을 그대로 다시 쓴다(load → compute_grades → build_inputs → compute_sku → validate → summarize).
- 가중치만 바꾼 `PurchaseMasterRow` 사본으로 후보마다 다시 계산한다. 탐색 로직은 순수 함수로 둔다.

**Tech Stack:** Python 3.12, openpyxl, pytest, uv

**Spec:** `docs/superpowers/specs/2026-11-20-가중치-탐색-design.md`

## Global Constraints

- 후보: `CANDIDATES = (0.0, 0.1, …, 1.0)`(round(i/10, 1)). FCST가중치 = round(1 − w, 1).
- 선택 구간 `range(35, 39)`, 검증 구간 `range(39, 44)`, 참고 전체 구간 `range(35, 44)`. 이 값이 기본값이고 명령줄로 바꿀 수 있다.
- 작은 그룹: 선택 구간 가중평균 수요오차가 있는 SKU가 `MIN_GROUP_SKUS = 5` 미만이면 공통 최적값을 쓴다. 공통 최적값은 모든 SKU를 합친 WAPE가 가장 낮은 w다.
- 고르는 기준: 선택 구간 가중평균 WAPE 최소. 동점(차이 1e-12 이하)이면 현재 w와의 거리가 작은 쪽, 그래도 같으면 작은 w.
- 선택에는 검증 구간 실제 출고를 쓰지 않는다.
- 코드 주석·docstring·커밋 메시지·README는 한국어, 식별자는 영어.
- `uv run pytest` 전부 통과.

## Review Focus

1. **그룹이 None인 SKU:** 구매마스터에 없는 SKU는 그룹이 None이다. 이런 SKU는 가중치가 없어 채점에서 빠진다. 탐색에서는 그룹 키 '미분류'로 세되 가중치는 적용하지 않는다(Task 1 테스트).
2. **현재 w가 그룹 안에서 제각각인 경우:** 그룹 안에서 가장 많이 나오는 값을 현재 w로 본다. 동수면 작은 값이다(Task 1 테스트).
3. **WAPE가 None(실제 합 0):** 해당 후보는 비교에서 뺀다. 모든 후보가 None이면 현재 w를 유지하고 선택 방식은 `현재유지`다(Task 1 테스트).
4. **선택이 검증 구간에 의존하지 않음:** 검증 구간 실제 출고만 바꾸면 선택 w가 같아야 한다(Task 1 테스트).

**Interfaces:**
- Consumes:
  - 로더: `load_purchase_master`, `load_sales`, `load_onhand`, `load_summary`, `load_weekly_plan`
  - 계산: `compute_grades`, `build_inputs(..., grades=)`, `compute_sku`, `CalcSettings`
  - 검증: `validate(results, actual_sales, weeks)`, `summarize(rows) -> list[SummaryMetric]`
  - 로드 순서와 보정계수 가져오는 방식은 `inventory_days/report.py`의 `run`과 같게 한다.
- Produces (`search.py`):
  - `CANDIDATES`, `MIN_GROUP_SKUS`
  - `current_weights(pm: dict[str, PurchaseMasterRow]) -> dict[str, float]`: 그룹 → 현재 w(최빈값, 동수면 작은 값). 그룹이 None인 행은 뺀다.
  - `with_weights(pm, weights: dict[str, float]) -> dict[str, PurchaseMasterRow]`: 그룹이 weights에 있는 행만 `weight_actual=w, weight_fcst=round(1-w,1)`로 바꾼 사본.
  - `group_wape(rows: list[ValidationRow]) -> dict[str, tuple[int, float | None]]`: 키는 '전체'와 그룹명(None은 '미분류'), 값은 (SKU 수, WAPE). 대상은 `checks['가중평균'].error_week`와 `actual_week_avg`가 모두 있는 행이다. WAPE = Σ|오차| / Σ실제이고, Σ실제 = 0이면 None이다.
  - `@dataclass(frozen=True) Choice`: `group: str, n: int, current: float, chosen: float, method: str`. method는 `'그룹최적' | '공통최적' | '현재유지'`.
  - `choose(table: dict[float, dict[str, tuple[int, float | None]]], current: dict[str, float]) -> list[Choice]`: w → group_wape 결과 표를 받아 그룹별로 고른다. 그룹 순서는 `current`의 순서다.
  - `@dataclass(frozen=True) SearchResult`: `table`, `choices: list[Choice]`, `metrics: dict[tuple[str, str], list[SummaryMetric]]`. metrics 키는 (구간 라벨 `'검증'|'전체구간'`, 가중치 라벨 `'현재'|'탐색'`)이다.
  - `run_search(base: Path, actual: Path, settings: CalcSettings, select_weeks: range, holdout_weeks: range, full_weeks: range) -> SearchResult`
- Produces (`report.py`): `write_search_report(path, result: SearchResult, meta: dict[str, str]) -> None`. 시트는 `['후보성능', '선택가중치', '검증비교', '적용기준']`이다.
  - `후보성능` 열: `범위, 실적가중치, SKU수, WAPE`
  - `선택가중치` 열: `품목그룹, SKU수, 현재가중치, 선택가중치, 선택방식, 현재WAPE(선택구간), 선택WAPE(선택구간)`
  - `검증비교` 열: `구간, 범위, 가중치, 기준, 수요비교SKU수, WAPE, 편향, LT검증SKU수, 결품방어율, 실제기준재고일수중앙값`. 행은 기준 `가중평균`·`기존수기`만, 범위는 `전체`와 그룹 범위다(summarize의 scope 그대로).
- 명령줄: `python -m safety_stock.weight_search BASE --actual ACTUAL -o OUT [--select-weeks 35-38] [--holdout-weeks 39-43]`
  - 전체구간은 선택 시작~검증 끝이다.
  - 주차 형식은 `safety_stock.__main__._weeks`를 재사용한다.
  - InputError가 나면 종료 코드 2다.
  - 끝나면 그룹별 `그룹: 현재 w → 선택 w (방식)` 줄과 `검증 구간 가중평균 WAPE: 현재 x.x% → 탐색 y.y%`를 출력한다.
