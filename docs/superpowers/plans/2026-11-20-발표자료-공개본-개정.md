# 발표자료 공개본 개정 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공개본 15장을 "품목별 일별 안전재고 자동 산출(가중평균 대표, 실적기준·FCST기준 비교) → AI 보정" 흐름으로 다시 만든다.

**Architecture:**
- `presentation/extract.py`에 세 기준 안전재고일수 분포와 사례 품목의 세 기준 값을 추가한다. 그다음 `presentation/data.json`을 다시 만든다.
- `presentation/build_public.js`의 15장 본문을 설계 §2 표대로 다시 쓴다. 양식 도우미(slide, tag, footer, table, bars, box, icon 등)는 그대로 쓴다.

**Tech Stack:** Python 3.12(uv, openpyxl, pytest), Node(pptxgenjs, jszip), PowerPoint COM 렌더(`presentation/render.ps1`)

**Spec:** `docs/superpowers/specs/2026-11-20-발표자료-공개본-개정-design.md` (비식별 규칙은 `2026-11-20-발표자료-공개본-design.md` §2)

## Global Constraints

- 15장 이하. `uv run python presentation/leak_check.py out/발표_적정재고일수_공개본.pptx --max-slides 15`가 통과해야 한다.
- 화면 글자에 다음 말을 쓰지 않는다.
  - 금지어: MP, ITSM, SCM, WMS, 구매마스터, Logic, 사진, 가상, 엑셀, xlsx, 날짜(8/24 등), Z값 숫자, 보정계수, 서론·본론·결론
  - "근거 없", "1단계", "현재 여기", "Level"
- "MP 엔진"은 "기존 수요예측 엔진"으로 쓴다. FCST는 처음 나올 때 "FCST(예측)"로 풀어 쓴다.
- 기존 "현재 w"는 "현업 w"로 쓴다. 가중치는 "현업이 자체 공식으로 산정한 값"이라고 설명한다.
- 숫자는 모두 data.json에서 읽는다. 손으로 적은 숫자는 없다.
- 장마다 범위를 적는다.
  - 세 기준 비교: W35~43, 공통 74 SKU
  - AI 보정: 검증 구간 W39~43, 77 SKU
- 나빠진 지표도 적는다: 가중평균의 결품 방어율이 기존 수기·실적기준보다 낮다. AI 보정 후 방어율이 62.3% → 60.9%로 낮아졌다.
- 그룹은 그룹 A~G 별칭만 쓴다(기존 `ga()`). 절대 수량은 쓰지 않는다.
- 코드 주석은 한국어로 쓴다.

## Review Focus

- 실적기준·FCST기준 안전재고일수의 극단값(최대 427일, 96일): 최솟값~최댓값만 보이면 오해를 산다. P10~P90을 주 범위로 쓰고 최댓값은 보조로 표시한다. Task 1 테스트에서 분위수 값을 고정한다.
- 기준 값이 None인 SKU: 네 값이 모두 있는 SKU만 `bases`에 넣는다. 그래서 기준마다 n이 같다. Task 1 테스트에서 None 행이 빠지는지 확인한다.
- 사례 품목의 실적·FCST기준 방어 값이 None(채점 제외)일 수 있다. 화면에는 '–'로 보이고 빌드는 실패하지 않아야 한다. Task 2에서 cov()·'–' 처리를 한다.
- 그룹 히트맵에서 한 기준의 wape가 None인 그룹은 빈 칸('–', 회색)으로 그린다. Task 3에서 처리한다.
- 금지어 경계: "MP"는 영문 경계로 찾는다. "MLOps"는 걸리지 않지만 "MP엔진" 같은 표현은 걸린다. Task 4에서 leak_check로 확인한다.

**Interfaces:**
- Produces:
  - `basis_spread(values: list[float], old: list[float]) -> dict`
    - 반환 키: `median`, `min`, `max`, `p10`, `p90`, `distinct`, `shorter`
    - `distinct`는 소수 1자리로 반올림한 고유값 수다.
    - `shorter`는 같은 위치의 old보다 작은 개수다.

  - `safety_distribution(calc)['bases']`

  - `case_dict(...)` 추가 키
    - 기준 `b`는 실적기준·FCST기준이고, 접두는 `act`·`fc`다.

    - `{p}_cover`: 검증 `{b}_LT수요방어`

### Task 3: 공개본 9~10장 (세 기준 채점과 그룹별 히트맵)

**Files:** Modify `presentation/build_public.js`(새 9·10장 블록)

**Interfaces:**
- Consumes: `M`, `BASIS3`, `BLABEL`(Task 2), `D.metrics[그룹코드]`, `ga()`, `groupsOrdered`

9장:
- KPI 세 줄(WAPE, 결품 방어율, 재고일수 중앙값) × 네 기준 표를 넣는다.
- 가장 좋은 값은 청록으로 칠한다. 오차율은 낮을수록, 방어율은 높을수록 좋다.
- 제목은 data로 만든다. 최솟값 wape 기준이 가중평균이면 "가중평균 기준이 실제 출고에 가장 가깝습니다"로 쓰고, 아니면 사실대로 쓴다.
- 맞바꿈 해석 줄: 기존 수기는 방어율이 가장 높지만 재고일수 중앙값도 가장 길다. 이 문장도 조건부로 쓴다.

10장:
- 그룹 A~G × 세 기준 wape 히트맵을 그린다. 행 안 최솟값에 ★을 붙이고, None은 회색 '–'로 둔다.
- 그룹별 SKU 수 열을 넣는다(`n_demand` 가중평균).
- 결론 줄: 가장 맞는 기준이 가중평균이 아닌 그룹을 나열하고, "그룹별 가중치를 보정할 여지"로 다음 장과 잇는다.
